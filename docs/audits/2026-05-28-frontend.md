### P0 #1 — `agentation` debug toolbar в production

**Что**: В `src/app/layout.tsx:113` стоит `<Agentation />`, который рендерится на каждой публичной странице. В bundle это 417 KB JS-чанк (`dc07ed8c-cafbf11add59bc73.js`). Также рендерится в admin-ветке (line 53) — это ок.

**Почему проблема**:
- Дебаг-инструмент для аннотаций видим/доступен любому посетителю production-сайта.
- Раздувает First Load на каждой странице (включая лендинг — критично для conversion и SEO Core Web Vitals).
- Memory user_collaboration `[Pre-launch state]` помечает «debug widgets like Agentation OK on prod for now» — но «for now» уже истекает: до релиза 2-4 недели.

**Что сделать**:
```tsx
// src/app/layout.tsx
{process.env.NODE_ENV !== 'production' && <Agentation />}
```
Или гейт через env-флаг `NEXT_PUBLIC_ENABLE_AGENTATION`. После релиза — удалить пакет полностью (`npm rm agentation`).

**Effort**: S (5 мин)

### P0 #2 — `getCurrentPath()` use of `__dirname` is broken

**Что**: В корневом layout'е `generateMetadata` вызывает `getCurrentPath()` для построения canonical:

```ts
// src/app/utils/constants.ts:269
export function getCurrentPath():Array<string>{
    let currentDir:RegExpMatchArray|null = __dirname.match(/(?<=[\/\\]app[\/\\]).+/)
    let path:Array<string> = []
    if (currentDir){
        path = currentDir[0].split(/\/\\]/)  // ← regex /\/\\]/  — это синтаксически broken split
    }
    return path
}
```

```ts
// src/app/layout.tsx:24,32
let path = getCurrentPath()
// ...
canonical: SITE_INFO.domain + '/' + path.join('/'),
```

**Почему проблема**:
1. `__dirname` в Next.js — это build-time path к скомпилированному файлу (нечто вроде `.next/server/app`), а не runtime route.
2. Regex split `/\/\\]/` — некорректный паттерн (не разделяет ни на что осмысленное; пробует найти `/\]` буквально).
3. В итоге каждая страница получает canonical, который **либо пустой, либо мусорный, либо одинаковый для всех страниц**.
4. SEO-импакт: дубликаты canonical → потеря rank по большинству страниц.

**Что сделать**:
- В Next.js App Router читать `pathname` через `headers().get('x-pathname')` (уже выставляется middleware'ом!).
- Либо: использовать `usePathname()` в client-компоненте и не пытаться делать canonical в server-layout.
- Простейший фикс:

```ts
// src/app/layout.tsx
export async function generateMetadata(): Promise<Metadata> {
  const pathname = headers().get('x-pathname') ?? '/';
  return {
    verification: { yandex: "35381404e7bfd3a4" },
    metadataBase: new URL(SITE_INFO.domain),
    alternates: {
      canonical: pathname,
    },
  }
}
```
И удалить `getCurrentPath` из `constants.ts`.

**Effort**: S (15 мин)

### P0 #3 — `ProductCardsBlock` malformed image URL fallback

**Что**: В каталоге товаров на `/shop`:

```tsx
// src/components/pages-components/shop-page/product-cards-block/product-cards-block.tsx:41
const url = item?.image_url ? `${apiBaseUrl}${item.image_url}` : '';
```

где `apiBaseUrl = 'https://pnhdstudioapi.ru'` и `item.image_url` — уже **полный** URL вида `https://cdn.pnhd.ru/<slug>_0.jpg` (см. миграцию `20260527000004_import_catalog.sql`).

Результат: `https://pnhdstudioapi.ruhttps://cdn.pnhd.ru/<slug>_0.jpg` — невалидный URL, 404.

В `product-card.tsx` есть многоступенчатый fallback:
```tsx
// product-card.tsx:19,42-46
const [imageSrc, setImageSrc] = useState(`${CDN_URL}/${slug}_0.jpg`);  // OK — пробуем CDN
onError={() => {

    setImageSrc(img ?? '');  // ← здесь падает на сломанный url

    setImageError(true);  // → no%20photo.png
  }
```

### P1 #6 — IntersectionObserver re-init storm в `ProductCardsBlock`

**Что**:
```tsx
// product-cards-block.tsx:14
const observerOptions = {
  root: null,
  rootMargin: '0px 0px 50px 0px',
  threshold: 0.1,
}
// ...
useEffect(() => { ... }, [observerRef, endIndex, observerOptions])
```

`observerOptions` — inline object, новая ссылка на каждый render. Эффект пере-запускается на любой родительский render. Плюс `shopData` нет в deps, хотя body использует `shopData.length`.

**Почему**: на каждом фильтре/смене URL-параметров observer полностью пере-создаётся (disconnect + observe). Не критично, но в DevTools видна суета.

**Что сделать**:
```tsx
const OBSERVER_OPTIONS = { root: null, rootMargin: '0px 0px 50px 0px', threshold: 0.1 } as const;

useEffect(() => {
  const target = observerRef.current;
  if (!target) return;
  const observer = new IntersectionObserver((entries) => {
    const [entry] = entries;
    if (entry.isIntersecting && endIndex < shopData.length) {
      setEndIndex((i) => i + 8);
    }
  }, OBSERVER_OPTIONS);
  observer.observe(target);
  return () => observer.unobserve(target);
}, [endIndex, shopData.length]);
```

**Effort**: S (5 мин)

## What's good

Список того, что в проекте уже сделано правильно — **не сломать при правках**:

1. **3D `<Tee>` через `dynamic({ssr:false, loading: TeePlaceholder})`** — three.js и drei НЕ попадают в SSR-бандл и lazy-грузятся только на лендинге. Бандл-разделение работает: 671 KB three-чанк отдельно.

Schema bump `order_v2 → order_v3` + валидация restored data (включая enum `location` и `files`) в [cart-icon.tsx:42-65](src/components/shared-components/cart-icon/cart-icon.tsx#L42). Грамотно.

5. **Edge middleware пробрасывает `x-pathname` в request headers** для root layout — это правильный паттерн App Router, layout может различать admin/public без `usePathname()` в client.

8. **Сanvas-isolation MUI-импорты в admin** работают: shared barrel `from '@mui/material'` или конкретные deep-imports (`@mui/icons-material/Edit`) — оба обрабатываются MUI v7 + Next 14 tree-shaking корректно.

10. **RTK Query endpoints с явными generics** `builder.query<Response, Args>` / `builder.mutation<Response, Args>` — type-safe (кроме `promocodeValidation` с `unknown` return).
