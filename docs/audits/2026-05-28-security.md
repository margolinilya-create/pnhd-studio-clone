## Summary

Кодовая база в **существенно лучшем** состоянии чем средний клон под cutover: тройная защита админки (middleware → `requireAdmin()` → RLS) фактически работает, `service_role` не утекает в client bundle (grep чистый), `'server-only'` стоит на admin-клиенте, RLS на `leads` плотный (anon-insert удалён, пишет только Edge Function), Storage path-prefix RLS на `user-uploads/prints/` есть, retention pg_cron'ы настроены, blog body санитизуется через DOMPurify. Поверх этого — **три эксплуатируемые уязвимости** и **одно прямое нарушение 152-ФЗ**, которые надо закрыть до DNS-свитча: (1) rate-limit Edge Function `create-lead` обходится одной строкой curl через подмену `X-Forwarded-For`; (2) `user-uploads` bucket публичный С разрешённым **листингом** — анон может выгрузить полный реестр всех клиентских принтов; (3) сломанный regex sanitizer в Edge Function (literal newline в char class); (4) хранение ПДн граждан РФ в Supabase eu-central-1 — после 1 июля 2025 это **прямое нарушение ст. 18 ч. 5 152-ФЗ**, штраф до 6 млн ₽ за первое нарушение / до 18 млн ₽ за повторное.

Из P1 главное: отсутствуют security headers (CSP / X-Frame-Options / X-Content-Type-Options / Referrer-Policy / Permissions-Policy — `curl -I` подтвердил, на production стоит только HSTS); Sentry/observability нет вообще («первые 24 часа после cutover в темноте»); admin-Tiptap upload берёт `File` без magic-bytes / pre-size-check / runtime bucket validation; sanitize-функция в create-lead матчит неизвестно что (см. P1 #3 ниже); Supabase Auth Leaked Password Protection выключен; client-side MIME-only на пользовательских загрузках принтов.

**Готовность к production-свитчу: P0 закрывать обязательно, иначе через час после DNS получим лид-спам в Bitrix24 (#1), утечку клиентских макетов в Telegram security-канал (#2), или иск от Роскомнадзора через 90 дней проверок (#4).** Реалистичный таймлайн фиксов — 2–3 дня по P0 + ещё 3–4 дня по P1 = укладываемся в 2–4 недели с запасом.

## OWASP Top 10 (2021) — detailed

### A01 Broken Access Control — **OK**

**Surface**: middleware `/admin/*` → `requireAdmin()` в Server Actions → RLS на write-таблицах. **Тройная защита фактически работает**.

- `middleware.ts:31-42` — guard в Edge middleware на каждый admin-роут
- `requireAdmin()` — re-query `admin_users` в каждом Server Action, бросает `Unauthorized/Forbidden` ([require-admin.ts:17-30](../../src/app/admin/_lib/require-admin.ts#L17))
- RLS — на `products`/`blog_posts`/`gallery_images`/`leads` write — `is_admin()` ([20260527000006_admin_rls.sql])
- `admin_users` — **нет INSERT/UPDATE/DELETE policy**, поэтому даже залогиненный admin не может через PostgREST добавить нового админа (только через Supabase Dashboard SQL Editor + service_role). Защита от privilege-escalation работает.
- `safeNextPath()` блокирует open-redirect на login ([login/actions.ts:9-13](../../src/app/admin/login/actions.ts#L9))
- Все 17 Server Actions через `'use server'` — проверено sub-агентом, каждая вызывает `requireAdmin()` ПЕРЕД `createAdminClient()`. **Никаких bypass-путей**.

**Минорные findings** (см. P1 S9, S15): `upload-image.ts` принимает `bucket` параметр без runtime-проверки (TS-only), `updateLeadStatus` принимает status string без zod-enum.

### A02 Cryptographic Failures — P1 / P0

- ✅ TLS через Vercel — HSTS работает на production curl (`max-age=63072000; includeSubDomains; preload`)
- ✅ Service-role key — `'server-only'` import, grep по `src/` чистый
- ✅ Cookies (Supabase Auth) — `httpOnly`, `secure` через `@supabase/ssr`
- ❌ **`ip_hash = sha256(ip)` без соли** (P1 #S7). IPv4-пространство ~4.3 млрд хешей. На современном GPU полный rainbow-table SHA-256 over IPv4 — минуты. После compromise БД (Supabase breach / админ-ноут украли) → восстановление всех IP за неделю. Роскомнадзор и российские суды считают IP персональными данными ([cyberosnova.ru](https://152fz.cyberosnova.ru/blog/ip-adres-personalnye-dannye)).
- ⚠️ **`cleanup-user-uploads` timing-leak secret compare** (P1 #S6). Edge runtime + сетевой шум делают атаку дорогой на практике, но defense-in-depth не выполнен.

### A03 Injection — **OK**

- ✅ SQL — везде Supabase client, никакого raw SQL через `rpc()` с user input. `link-search-action.ts:25` использует `ilike('%${query}%')` — PostgREST экранирует параметры, не SQL inject.
- ✅ Server Actions zod-валидация — на `saveProduct` ([save-action.ts:14]), `savePost` ([blog/save-action.ts:14]) ✓; **отсутствует** на `updateLeadStatus` (P1 #S15) и admin upload-image bucket arg (P1 #S9).
- ✅ Edge Function inputs — length-clamped + regex-валидированы. Source whitelist — `ALLOWED_SOURCES` ([create-lead/index.ts:26-32]).
- ❌ **Sanitize regex broken** (P0 #S3) — см. detailed ниже.
- ✅ HTML injection — `dangerouslySetInnerHTML` × 6 мест ([grep src/]):
  - `/blog/[post]` — body санитизуется через `isomorphic-dompurify` в admin write-path ✓
  - `/methods/[slug]`, `/methods/[slug]/[type]`, `/textile/[slug]`, `/prints/[slug]` — content из TS-литералов в `src/app/utils/*-options-data.ts` (controlled developer) ✓
  - `markup-script.tsx` — JSON-LD, controlled output ✓
  - **Все ок при текущем дизайне** (контент не редактируется через UI). Если когда-нибудь методы/принты переедут в admin-таблицу — обязательно DOMPurify.
- ⚠️ CSRF — Server Actions у Next.js защищены автоматически (Origin check на POST + cookie SameSite). Edge Function `create-lead` имеет Origin allowlist (P1 #S6 — но не идеально, см. ниже). Сервер-server вызовы без Origin пропускаются ([create-lead:207](../../supabase/functions/create-lead/index.ts#L207)) — это сделано для SSR, но любой curl без Origin тоже пройдёт. С учётом rate-limit (P0 #S1 уже сломан) — не уязвимость, но дыра в логике.

### A04 Insecure Design — **P0 / P1**

**Rate-limit bypass** (P0 #S1): см. exploit ниже. Дизайн сделан в предположении доверия `X-Forwarded-For`, что некорректно для публичного endpoint'а.

**File upload abuse** (P1 #S9, S10):
- Polyglot PNG-JS: атакующий собирает файл с валидным PNG header + JS payload в комментарии, загружает в `user-uploads` (MIME проверяется только по `file.type` from browser), потом ссылается `<script src="https://...supabase.co/storage/...png">` со стороннего сайта — если у нас CSP без `script-src` (см. P0 #S5), polyglot загрузится как скрипт через MIME-sniff (X-Content-Type-Options отсутствует, P0 #S5).
- DoS Storage: anon заливает 20 MB × 1000 = 20 GB за час (нет rate-limit на Storage upload — только бакет file-size cap). Free Supabase Storage = 1 GB. **Тариф переполнится за час → деплой остановится** (Supabase pause).

**Cart price manipulation**: пользователь меняет `price: 1500 → 1` в sessionStorage `order_v3`. Сейчас НЕ критично: чекаут не оформляет реальный заказ (demo-alert), лиды через Edge Function ходят без price (только name+phone+comment). После реального чекаута — обязательно server-side recompute из БД.

### A05 Security Misconfiguration — **P0 / P1**

`curl -I https://pnhd-studio-clone.vercel.app/`:
```
strict-transport-security: max-age=63072000; includeSubDomains; preload  ✓ (Vercel default)
x-powered-by: Next.js                                                     ✗ leak
[нет Content-Security-Policy]                                             ✗ P0
[нет X-Frame-Options]                                                     ✗ P0 — clickjacking
[нет X-Content-Type-Options]                                              ✗ P0 — MIME-sniff
[нет Referrer-Policy]                                                     ✗ P1
[нет Permissions-Policy]                                                  ✗ P2
```

Vercel default добавляет HSTS, но всё остальное — наша задача.

**Конкретный exploit X-Frame-Options отсутствия**: атакующий делает страницу `evil.ru/win-iphone` с `<iframe src="https://studio.pnhd.ru/admin/login" style="opacity:0">` + CSS-overlay кнопок «получить приз», которые на самом деле клики по login form. Если админ открыл evil.ru → UI redress → угнанная сессия.

**`metadataBase = localhost:3000`** (frontend P0 #4) — misconfiguration, не security per se, но соц-шеры с `og:image: http://localhost:3000/og.jpg` — позор бренда.

**Source maps**: Next.js default — sourcemaps только в dev. В production `.map` не генерится, если не выставлено `productionBrowserSourceMaps: true`. Проверено — не выставлено ✓.

### A09 Security Logging and Monitoring Failures — **P1 (critical)**

**Самый слабый раздел.**

- ❌ **Sentry нет** — frontend JS exceptions и backend Server Action throws нигде не агрегируются. После cutover на DNS первые 24 часа в темноте.
- ⚠️ **Vercel logs** — есть, retention 24 часа на free tier. Для incident response через 48 часов уже нечего смотреть (P1 #S17).
- ✅ **Edge Function logs** — `console.log`/`console.error` идут в Supabase logs (доступны через MCP `get_logs` или Dashboard). Retention на free tier — 1 день для analytics, 1 час для logs. Опять же недостаточно.
- ⚠️ **Telegram notifications** — есть только для нового лида (`notifyTelegram` в create-lead), но **НЕ для ошибок 5xx, не для admin failed login, не для rate-limit hit'ов**. После compromise админа не узнаете до visualного мониторинга.
- ⚠️ **Storage access logs** — Supabase free tier их не хранит retention'ом, видно только в реальном времени.
- ❌ **Audit log на admin actions** — нет таблицы `audit_log(actor_id, action, target, payload, at)`. Если завтра кто-то удалит все товары через admin UI — не узнаете, кто.

**Минимум до релиза**:

## 152-ФЗ соответствие — **критическое**

### Что собираем
`leads` table колонки: `name, phone, email, comment, reference_url, source, roistat_visit, user_agent, ip_hash`. Это ПДн в смысле ст. 3 152-ФЗ.

### Изменение 1 июля 2025 — ключевое для нас

С 1 июля 2025 действует обновлённая ч. 5 ст. 18 152-ФЗ: **первичный сбор ПДн граждан РФ (включая запись, систематизацию, накопление, хранение) должен происходить ИСКЛЮЧИТЕЛЬНО на серверах на территории РФ**. Использование иностранных облаков для первичной обработки прямо запрещено ([b1.ru](https://b1.ru/insights/law-messenger/localization-of-personal-data-of-russian-citizens-6-march-2025/), [comply.ru](https://comply.ru/tpost/c43ezsout1-lokalizatsiya-i-transgranichnaya-peredac), [b-152.ru](https://b-152.ru/hranenie-personalnyh-dannyh-za-granicej)).

**Наша инфра**: Supabase project `almfjmiygtnzngkayhdv` в регионе `eu-central-1` (Frankfurt). **Это нарушение закона.**

**Штрафы** (ст. 13.11 КоАП после поправок 2024):
- Первое нарушение для юр. лиц: 1–6 млн ₽
- Повторное: 6–18 млн ₽
- + блокировка домена/IP по решению Роскомнадзора

**Что говорят разъяснения**:
- ✅ Трансграничная передача ранее собранных в РФ данных — разрешена (Минцифры, май 2025)
- ❌ Первичный сбор в иностранный облако — запрещён, без исключений
- ⚠️ Hashing/anonymization не освобождает от локализации, если данные изначально идентифицируемы — Роскомнадзор смотрит на цель обработки, не на форму хранения

### Варианты решения (в рамках constraint «не мигрировать на другие облака»)

Constraint в задаче запрещает миграцию, но **закон выше constraint'а**. Озвучиваю варианты:

**A. Принять риск (smallest-effort)**. Для микро-бизнеса в первый год обычно проверки не приходят сразу — реактивно. Если жалоба не поступит — может пройти. **Не рекомендую**, потому что:
- автоматический мониторинг по доменам РФ растёт с 2025
- если упомянет конкурент / недовольный клиент / Роскомнадзор-сканер — штраф + блокировка
- риск персональной ответственности владельца через дисквалификацию

**B. Гибрид: лиды напрямую в Bitrix24, без Supabase`leads`**. Bitrix24 cloud работает в РФ (датацентры в Москве — поддерживается российской юрисдикцией). Edge Function `create-lead` уже умеет проксировать в Bitrix24 через webhook. Шаги:
1. Установить `BITRIX_WEBHOOK_URL` в Supabase secrets — функция уже это поддерживает
2. **Не писать в `public.leads`** — удалить `supabase.from('leads').insert(...)` из Edge Function, оставить только Bitrix24 + Telegram. Сложность: rate-limit сейчас опирается на `leads.ip_hash`. Заменить на in-memory кэш Deno (deno-kv или просто `Map` в module scope — серверов несколько, кэш не консистентный, но для anti-spam достаточно).
3. Не хранить ip_hash, user_agent в любой БД вообще

**C. Self-host PostgreSQL в РФ** (selectel/timeweb/cloud.ru/yandex.cloud Managed PostgreSQL — все российские). Сложно: миграция всей текущей схемы + storage + edge functions. Не укладывается в 2–4 недели. **Не для текущего таймлайна**.

**D. Минимум для попытки compliance**: даже если оставляем Supabase eu-central-1 — обязательно:
1. Уведомить Роскомнадзор о обработке ПДн (форма на сайте РКН) — статья 22 152-ФЗ обязывает оператора
2. Назначить ответственного за обработку ПДн (имя в Privacy)
3. Реализовать процедуру «удаление по запросу субъекта» (email на STUDIO@PNHD.RU + ручное удаление из БД)
4. Хранить «согласие на обработку» — checkbox checkbox в каждой форме привязан к timestamp в БД
5. Опубликовать Политику обработки ПДн с указанием места хранения (даже если это нарушение — формальная честность снижает риск)

**Рекомендация для cutover**: вариант **B** (лиды через Bitrix24, без локального хранения). Минимизирует юридический риск, сохраняет функциональность. Эффорт: 4–6 часов работы.

## Detailed P0 findings

### S1 — Rate-limit create-lead bypass через X-Forwarded-For

**Что**: [supabase/functions/create-lead/index.ts:114-120](../../supabase/functions/create-lead/index.ts#L114):

```ts
function extractIp(req: Request): string {
  const cf = req.headers.get('cf-connecting-ip');
  if (cf) return cf;
  const fwd = req.headers.get('x-forwarded-for');
  if (fwd) return fwd.split(',')[0].trim();
  return 'unknown';
}
```

`cf-connecting-ip` стоит первым (от Cloudflare), но мы НЕ за Cloudflare — мы за Supabase Edge (Deno Deploy). Этот header НЕ выставляется автоматически. `x-forwarded-for` — берётся **первое значение**, что **управляется клиентом**.

**Exploit**:
```bash
for i in {1..1000}; do
  curl -X POST "https://almfjmiygtnzngkayhdv.supabase.co/functions/v1/create-lead" \
    -H "Origin: https://studio.pnhd.ru" \
    -H "Content-Type: application/json" \
    -H "apikey: <anon-key>" \
    -H "X-Forwarded-For: 1.1.${RANDOM}.${RANDOM}" \
    -d '{"name":"spam","phone":"+79001234567","source":"footer"}' &
done
```

→ 1000 заявок за минуту:
- спам в `leads` (БД заполняется)
- 1000 webhook'ов в Bitrix24 (если `BITRIX_WEBHOOK_URL` задан — счёт заблокируют за abuse)
- 1000 Telegram-сообщений (если задан) — Telegram забанит бота
- забивает Supabase Edge invocations (free tier — 500k/month, через DDoS можно высушить за день)

**Fix**: вместо trust X-Forwarded-For — использовать **последнее** значение в цепочке (это будет реальный IP от Vercel/Deno edge proxy), или ещё лучше — Deno-нативный способ: в Deno deploy реальный IP клиента доступен через `Deno.serve` второй аргумент:

```ts
Deno.serve((req: Request, info: Deno.ServeHandlerInfo) => {
  const realIp = info.remoteAddr.hostname;  // ← это IP edge proxy, не клиента
  ...
});
```

**Проблема**: Supabase Edge Functions работают на Deno Deploy, который сам является terminating proxy. `info.remoteAddr` — это IP **Deno edge node**, не клиента. Реальный клиентский IP **приходит ТОЛЬКО** через `x-forwarded-for`, но **последнее** значение в списке — это IP Deno proxy, а **предпоследнее** — реальный клиент:

```ts
function extractIp(req: Request): string {
  const fwd = req.headers.get('x-forwarded-for');
  if (!fwd) return 'unknown';
  const ips = fwd.split(',').map(s => s.trim());
  // Берём предпоследний — это IP клиента после прохода через Deno edge.
  // Последний — IP Deno edge node, его spoof'ить нельзя.
  // Но любой промежуточный — управляется клиентом.
  return ips.length >= 2 ? ips[ips.length - 2] : ips[ips.length - 1];
}
```

Это требует проверки на реальной Edge Function (через test request с известным IP и логированием полного X-Forwarded-For). **Перед фиксом — обязательно залогировать сырой XFF из реального запроса**, чтобы понять, сколько hops добавляет Deno.

**Альтернатива (надёжнее)**: rate-limit по `(ip_hash, user_agent_hash, fingerprint)` композитному ключу — атакующему придётся варьировать UA + cookies + fingerprint, что серьёзно усложняет ботнет. Или **обязательная CAPTCHA**.

**Severity**: P0. **Effort**: XS (1-2 строки + verify).

### S2 — `user-uploads` bucket позволяет LISTING

**Что**: [supabase/migrations/20260527000001_user_uploads_bucket.sql:23-27](../../supabase/migrations/20260527000001_user_uploads_bucket.sql#L23):

```sql
create policy "user-uploads public read"
    on storage.objects for select
    to public
    using (bucket_id = 'user-uploads');
```

Эта policy разрешает `SELECT` без path-фильтра. Это значит, что любой клиент может вызвать `storage.list('prints')`:

```bash
curl "https://almfjmiygtnzngkayhdv.supabase.co/storage/v1/object/list/user-uploads" \
  -H "apikey: <anon-key>" \
  -d '{"prefix":"prints/","limit":1000}'
```

→ JSON со **всеми** файлами в bucket:
```json
[
  {"name": "f3a2-customer-logo.png", "created_at": "...", "metadata": {"size": 2031421}},
  {"name": "8b1c-private-design.jpg", ...},
  ...
]
```

Дальше — `getPublicUrl(...)` даёт прямую ссылку на каждый. **Это утечка коммерческой графики клиентов**.

UUID-префиксы в именах файлов **не являются защитой** — listing их выдаёт. Reference от Supabase advisor: [public_bucket_allows_listing](https://supabase.com/docs/guides/database/database-linter?lint=0025_public_bucket_allows_listing).

**Fix**: убрать broad SELECT policy. Вместо этого — клиент должен знать точный path к своему файлу. Object access по path (через `getPublicUrl`) работает без RLS на SELECT, потому что bucket публичный (`public=true`). Конкретно:

```sql
drop policy if exists "user-uploads public read" on storage.objects;
-- НИЧЕГО не создаём вместо. Public bucket + точный path = доступ работает.
-- Listing — закрыт.
```

**Verify**: после миграции — анон не сможет `.list()`, но сможет `.getPublicUrl(path)` если знает path.

**Severity**: P0. **Effort**: XS (1 строка SQL).

### S3 — Сломанный sanitize regex в create-lead

**Что**: [supabase/functions/create-lead/index.ts:91-98](../../supabase/functions/create-lead/index.ts#L91), сырые байты:

```
.replace(/[\n    .replace(/\s+/g, ' ')
```

То есть после `/[` идёт **literal newline (0x0A)** и 4 пробела, и character class **не закрывается до конца цепочки**. JavaScript regex parser сканирует character class до первого unescaped `]`. Между `/[` и следующим `]` (в строке EMAIL_RE) — много байтов, поэтому regex компилируется во что-то неожиданное, или Deno бросает SyntaxError на парсе (но функция работает в production — значит компилируется в **какой-то** regex, просто не в тот, что задумали).

**Намерение разработчика**: видимо, `.replace(/[\x00-\x1f]/g, ' ')` — удалить control chars. По факту — матчит непонятно что, потенциально включая обычные буквы.

**Exploit (потенциальный)**:
- Атакующий вставляет в `name` или `comment` ANSI escape codes (`\x1b[31m`), которые проходят санитизацию (regex их не матчит) → попадают в Bitrix24 / Telegram сырыми → если открыть через ANSI-aware client — терминал-инъекция, спам визуализацией
- Atomic newlines в `name` — ломают логирование (рассылка по строкам)
- **Бóльшая проблема**: санитизация *неполная*. Защита от XSS / log-injection — фиктивная.

**Verify уверенности**: ниже EMAIL_RE парсится корректно (`EMAIL_RE = /^[^\s@]+@[^\s@]+\.[^\s@]{2,}$/i`) — значит JS-движок где-то нашёл закрывающий `]`. Возможно, в самом EMAIL_RE на `]+` regex literal закрывает первый, и тогда `EMAIL_RE` начинается с broken-state. Точный анализ требует AST через Deno parser.

**Fix**: переписать на явный escape:

```ts
function sanitize(input: unknown, max: number): string {
  if (typeof input !== 'string') return '';
  return input
    .replace(/[\x00-\x1f\x7f]/g, ' ')  // control chars
    .replace(/\s+/g, ' ')
    .trim()
    .slice(0, max);
}
```

**Severity**: P0 (защита фиктивна), но реальный exploit зависит от downstream. **Effort**: XS (1 строка).

### S5 — Отсутствие security headers

**Что**: `curl -I https://pnhd-studio-clone.vercel.app/` показывает только HSTS. Vercel НЕ добавляет CSP / X-Frame-Options / X-Content-Type-Options автоматически — это наша задача в `next.config.mjs`.

**Exploit clickjacking** (без X-Frame-Options):
```html
<!-- evil.ru -->
<style>
  iframe { opacity: 0.01; position: fixed; top: 0; left: 0; width: 100vw; height: 100vh; }
  .fake-button { position: fixed; top: 200px; left: 100px; padding: 20px; background: gold; }
</style>
<iframe src="https://studio.pnhd.ru/admin/login"></iframe>
<button class="fake-button">Выиграть iPhone!</button>  <!-- на самом деле — кнопка login -->
```

Админ кликает «iPhone» → клик идёт в скрытый iframe-login → если использует пасс-менеджер с autofill → перехват сессии cookies через дополнительный JS.

**Exploit MIME-sniff** (без X-Content-Type-Options):
- Пользователь загружает PNG-polyglot с embedded JS в `user-uploads/prints/`
- Атакующий на стороннем сайте `<script src="https://...supabase.co/storage/.../polyglot.png">`
- Браузер sniff'ит MIME → решает что это application/javascript → исполняет JS
- Если у нас CSP без allowed-script-src → даже на нашем домене defence отсутствует

**Fix**: в `next.config.mjs`:

```js
async headers() {
  return [
    {
      source: '/(.*)',
      headers: [
        { key: 'X-Frame-Options', value: 'DENY' },
        { key: 'X-Content-Type-Options', value: 'nosniff' },
        { key: 'Referrer-Policy', value: 'strict-origin-when-cross-origin' },
        { key: 'Permissions-Policy', value: 'camera=(), microphone=(), geolocation=(), interest-cohort=()' },
        // CSP — отдельно, см. ниже
      ],
    },
    {
      source: '/admin/:path*',
      headers: [
        { key: 'X-Robots-Tag', value: 'noindex, nofollow' },  // closes SEO P2 #35
      ],
    },
  ];
},
poweredByHeader: false,  // closes P1 #S16
```

**CSP** — отдельный challenge. Roistat/Metrica/uiscom требуют `'unsafe-inline'` для встроенных загрузчиков. Минимальная report-only CSP до production:

```js
{
  key: 'Content-Security-Policy-Report-Only',
  value: [
    "default-src 'self'",
    "script-src 'self' 'unsafe-inline' https://mc.yandex.ru https://cloud.roistat.com https://w.uiscom.ru",
    "img-src 'self' data: https://cdn.pnhd.ru https://almfjmiygtnzngkayhdv.supabase.co https://mc.yandex.ru",
    "connect-src 'self' https://almfjmiygtnzngkayhdv.supabase.co https://mc.yandex.ru https://cloud.roistat.com",
    "frame-ancestors 'none'",
    "base-uri 'self'",
    "form-action 'self'",
  ].join('; '),
}
```

Refs: [Next.js CSP guide](https://nextjs.org/docs/pages/guides/content-security-policy), [Vercel security headers](https://vercel.com/docs/cdn-security/security-headers), [Next.js security best practices 2026](https://www.authgear.com/post/nextjs-security-best-practices/).

**Severity**: P0. **Effort**: S (30 мин на P0 headers + Report-Only CSP; M на full enforced CSP).

## Incident response плейбук (минимум)

### 1. «Сайт упал / 5xx burst»
1. Открыть Vercel Dashboard → Deployments → текущий production → Logs (Runtime Logs)
2. Если ошибка очевидна — `git revert <commit>` и `git push main` (auto-redeploy)
3. Если не очевидна — Vercel Dashboard → Deployments → previous green → «Promote to Production»
4. После стабилизации — debug в новой PR-ветке

### 2. «Поток спам-лидов в Bitrix24 / Telegram»
1. Supabase Dashboard → Edge Functions → `create-lead` → Logs — увидеть pattern (один ip_hash или много?)
2. Если много ip_hash с одинаковым UA → ботнет → временно отключить Edge Function (Dashboard → Pause)
3. Если один — добавить блок-лист в коде Edge Function (deploy)
4. Альтернатива: временно увеличить rate-limit окно до 60 сек, max до 1
5. Включить CAPTCHA (P1 S13)

### 3. «Утечка данных / суспектный access к admin»
1. Supabase Dashboard → Auth → Users → admin user → «Sign out all sessions»
2. Сменить пароль через invite-link
3. SQL: `select * from public.audit_log where ... order by at desc limit 100` (если есть; сейчас нет — добавить P2 #S28)
4. SQL: `select * from public.leads where updated_at > <suspicious_time>` — что изменили?
5. Если service_role key leaked — Dashboard → Settings → API → Rotate service_role
6. Уведомить пользователей если их данные затронуты (152-ФЗ ст. 21 — обязательно в 72 часа)

### 4. «Supabase eu-central-1 уехал в downtime»
1. Check https://status.supabase.com — реально ли наш регион
2. Если да: ждать (свой инстанс не имеем)
3. Параллельно: статичная заглушка через Vercel `_offline.html` (нужен Service Worker — задача на P2)
4. После восстановления: проверить leads count vs последнего бэкапа — есть ли потери?

### 5. «GitHub репо взломан / leaked secret в коммите»
1. Vercel Dashboard → Settings → Git → Disconnect repo (остановит auto-deploy)
2. Supabase Dashboard → Settings → API → Rotate anon + service_role + JWT secret
3. Edge Function secrets — пересоздать BITRIX_WEBHOOK_URL, TELEGRAM_*, CLEANUP_SECRET
4. `git push --force-with-lease` после удаления secret из истории (через `git filter-repo`)
5. Reconnect Vercel → fresh deploy с новыми ключами

## Open questions

1. **152-ФЗ — какой подход выбираем?**
   - (A) Принять риск, ничего не менять — **не рекомендую**, штраф вероятен на горизонте года
   - (B) Гибрид: лиды напрямую в Bitrix24, без локального хранения — **рекомендую**, требует 4-6 часов
   - (C) Полная миграция на yandex.cloud / selectel — outside scope текущей задачи
   - Решение от владельца до спринта 1.

2. **Bitrix24 access** — есть ли уже доступ к админке и webhook URL? Без него вариант B не работает.

3. **Real X-Forwarded-For format в Supabase Edge** — нужно тестовый запрос с известного IP сделать через `curl --interface <known>` и в Edge Function `console.log(req.headers.get('x-forwarded-for'))`, чтобы понять, сколько hops добавляет Deno proxy. Без этого фикс S1 — на угадывание.

4. **Sentry — free tier (5k events/month) хватит?** Для маленького RU-only сайта на старте — да. После масштабирования (>5k unique visitors / day) — нужна платная подписка либо self-hosted Sentry (на selectel/timeweb).

5. **CAPTCHA — Яндекс SmartCaptcha или CloudFlare Turnstile?** SmartCaptcha от Яндекса — РФ-юрисдикция (152-ФЗ alignment), бесплатный, простая интеграция. Turnstile — не нужен в РФ-only контексте.

6. **Privacy policy ревизия** — кто пишет юридический текст? Владелец, юрист на аутсорсе, или взять шаблон с b-152.ru / Tilda?

7. **Telegram notifications для security incidents** — кто получает алерты в 3 ночи? Один владелец = single point of failure. На старте приемлемо, после релиза — рассмотреть backup-канал.

8. **Service-role key rotation procedure** — кто и как часто? Сейчас рекомендация: rotate раз в 90 дней + при любом подозрении на leak. Без CI это полу-ручная процедура (`vercel env` + Supabase Dashboard).

9. **Roistat / Yandex Metrica / uiscom IDs** — если владелец заменяет на свои, новые ID должны пройти CSP whitelist (если включаем enforced CSP — добавить новые домены).

10. **Backup retention** — Supabase free tier даёт 7 дней daily backups. Если нужно дольше — pg_dump через Supabase CLI + git LFS / S3-compatible. Решение до cutover.
